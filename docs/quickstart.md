# Run your first registry

This walkthrough creates a dedicated local K3s cluster, installs the operator and
its bundled Metacontroller, and creates a private registry backed by PostgreSQL.
Run the commands from the repository root.

## Prerequisites

Install Docker with its daemon running, [k3d](https://k3d.io/),
[kubectl](https://kubernetes.io/docs/tasks/tools/), [Helm 3](https://helm.sh/docs/intro/install/),
Python 3, and Make. Docker must be able to pull the pinned K3s, PostgreSQL,
Metacontroller and upstream registry images. The operator image is built locally;
you do not need a container registry account.

If you have several Docker runtimes, select the running one for the demo and its
cleanup. For Docker Desktop, for example, run `export DOCKER_CONTEXT=desktop-linux`
before `make demo-up`. The helper also accepts `K3D=/path/to/k3d` and uses the
repository's cached k3d binary when one is available and k3d is not on `PATH`.

The demo uses K3s NetworkPolicy enforcement, the `cluster.local` DNS domain, and
its own kubeconfig in `.local/quickstart/kubeconfig`. It does not use your current
cluster. The operator provisions PostgreSQL on a 1Gi PVC using the cluster's
default StorageClass. Pod replacement keeps its data; deleting the demo cluster
destroys that storage. Use this environment for learning only.

## 1. Install and create a registry

```sh
make demo-up
```

The command builds the operator image locally, creates the dedicated
`agentregistry-demo` cluster, loads the image, installs the Helm chart, generates
authentication credentials and applies
[`examples/private.yaml`](../examples/private.yaml). It waits for the
`tenant-a/catalog` registry to become Ready. The operator generates database
credentials and provisions PostgreSQL with `pg_trgm`, `vector` and a 1Gi volume.

Authentication credentials are generated once and stored in `.local/quickstart/`,
which is ignored by Git. Rerunning the command reuses those credentials. Database
credentials are generated by the operator in the immutable `catalog-postgres`
Secret and reused across reconciliations. Do not commit generated credentials or
share the whole directory.

Use the explicit demo kubeconfig for every command:

```sh
kubectl --kubeconfig .local/quickstart/kubeconfig -n tenant-a get agentregistries
kubectl --kubeconfig .local/quickstart/kubeconfig -n tenant-a get pods,services
```

The registry should report `VERSION=0.3.3`, `INSTALLED=0.3.3`, and `READY=True`.
PostgreSQL has the `catalog-postgres` StatefulSet; the registry Deployment contains
the `registry` and authenticated `gateway` containers.

## 2. Open the UI and query the catalog

Keep this running in a terminal:

```sh
kubectl --kubeconfig .local/quickstart/kubeconfig -n tenant-a \
  port-forward service/catalog 18080:8080 --address 127.0.0.1
```

Open [http://127.0.0.1:18080/](http://127.0.0.1:18080/) in your browser. Use the
username and password in `.local/quickstart/credentials.txt`. The browser prompts
for HTTP Basic authentication.

In another terminal, query the empty server catalog using the generated curl
configuration, which keeps the password out of command arguments:

```sh
curl --fail --silent --show-error \
  --config .local/quickstart/curl.conf \
  http://127.0.0.1:18080/v0/servers
```

The UI, API and MCP endpoints share the same credentials and listen on `/`, `/v0`
and `/mcp`. Authentication is required even when the catalog is empty. Access
inside the cluster is limited to pods in `tenant-a` by NetworkPolicy. HTTP Basic
authentication does not encrypt traffic; use the [TLS example](creating-a-registry.md#enable-https)
for a network-accessible deployment.

## 3. Inspect what you created

```sh
kubectl --kubeconfig .local/quickstart/kubeconfig -n tenant-a get areg catalog -o yaml
kubectl --kubeconfig .local/quickstart/kubeconfig -n tenant-a \
  get deployment/catalog service/catalog serviceaccount/catalog networkpolicy/catalog
kubectl --kubeconfig .local/quickstart/kubeconfig -n tenant-a \
  get statefulset/catalog-postgres service/catalog-postgres \
  configmap/catalog-postgres secret/catalog-postgres networkpolicy/catalog-postgres \
  pvc/data-catalog-postgres-0
```

The operator manages four application resources and five PostgreSQL resources;
the StatefulSet creates the database PVC. The namespace isolation policy and
authentication Secret are supplied separately. Deleting the registry retains
the PVC but deletes the generated database Secret, so back up both the database
and its Secret before deleting an installation you need to restore.

To change application resource sizing, edit `spec.resources` in a copy of the
[private example](../examples/private.yaml), then apply your copy. The
[API reference](api-reference.md) lists all available settings.

## 4. Clean up

Stop the port-forward with Ctrl-C, then delete only the dedicated demo cluster:

```sh
make demo-down
```

Deleting the cluster destroys its registry data. The helper retains local
credential files so you can inspect or reuse them; remove `.local/quickstart/`
separately when you no longer need those files.

For a registry on an existing cluster, follow [installation](installation.md)
and [creating a registry](creating-a-registry.md). For failed readiness checks,
see [troubleshooting](operations.md#troubleshooting).
